weavecode design system

Software, sewn to fit. This document tells designers and engineers how to use the system — same vocabulary, same tokens, same outcome on both sides of the handoff.

For designers

Pick a token, not a value rule

Never type #8127E8 in a design tool. Use the Purple / Brand token. If you reach for a hex, the system is missing something — flag it.

  • Color · use semantic tokens (brand, ink, muted) over raw scales when possible.
  • Type · use the scale (display, h1, body). Never an in-between size.
  • Spacing · stick to the 4px scale. 14px is forbidden.

One primary action rule

Per surface — modal, page, form. If two things "feel primary," one of them is wrong. Demote it to secondary or remove it.

  • Primary = filled Purple button.
  • Secondary = outline.
  • Tertiary = ghost / link.
  • Destructive = filled red — never the only red on the page.

Build all four states

Every async surface needs loading, empty, error, and success. Don't ship without all four mocked. The empty state is your second-best onboarding moment.

Test with the keyboard

Before handoff: tab through your design. Esc closes overlays. Focus rings are visible. Touch targets are 44×44 minimum. If a designer can't tab through it, neither can a screen-reader user.

For engineers

Setup

Drop the stylesheet at the top of every page. Tokens land as CSS custom properties on :root; semantic classes are utility-grade.

/* HTML */
<link rel="stylesheet" href="/weavecode/colors_and_type.css">

/* CSS */
.button-primary {
  background: var(--wc-purple);
  color: var(--wc-white);
  padding: var(--wc-space-2) var(--wc-space-4);
  border-radius: var(--wc-radius-md);
  font: 500 var(--wc-text-body) / 1.4 var(--wc-font-sans);
  transition: background var(--wc-dur-fast) ease-out;
}
.button-primary:hover { background: var(--wc-purple-600); }
.button-primary:focus-visible {
  outline: 3px solid var(--wc-orange);
  outline-offset: 2px;
}

Component anatomy

Every component documented in preview/ ships the same way: a token-only stylesheet, a working static HTML preview, and a props table in the README of its kit folder. No bespoke values inside components — if you need one, add it to the token system first.

  • Naming — --wc-{category}-{role}-{step?}. Examples: --wc-purple-500, --wc-text-body, --wc-radius-md, --wc-shadow-card.
  • Versioning — semver at the package level. Token additions = minor. Token removals or value changes that shift visuals = major.
  • Deprecation — keep deprecated tokens for one major version with a @deprecated comment + replacement noted.
Contribution rules
  • One reason to change. A pull request adds, edits, or removes one token / component. Bundled changes get sent back.
  • Document on commit. If it isn't in preview/ and the README, it doesn't exist.
  • Two-eyes minimum. One designer + one engineer must approve before merge.
  • Brand changes go through marketing. Type, primary colors, logo — not unilateral.
