**Codigo:**

```typescript
// apps/api/src/middleware/auth.middleware.ts

// Middleware que extrai o JWT e injeta no contexto tRPC.
// Todos os campos do JWT ficam disponiveis em ctx:
//   ctx.accountId  (sempre presente se autenticado)
//   ctx.tenantId   (presente se workspace selecionado)
//   ctx.memberId   (presente se workspace selecionado)
//   ctx.role       (presente se workspace selecionado)
//   ctx.plan       (presente se workspace selecionado)
```

Criar 3 niveis de procedure:

1. **publicProcedure** — sem auth. Qualquer um pode chamar.
2. **authedProcedure** — requer accountId no JWT. Pode nao ter tenantId (ex: antes de onboarding ou selecao de workspace).
3. **tenantProcedure** — requer accountId + tenantId no JWT. E o que a maioria dos routers de negocio vai usar.

O `authedProcedure` extrai `accountId` do token JWT (campo `sub`). Se nao existe, retorna erro `UNAUTHORIZED`.

O `tenantProcedure` herda do `authedProcedure` e adicionalmente exige `tenantId` (campo `tid`), `memberId` (campo `mid`), `role` e `plan`. Se qualquer um nao existe, retorna erro `FORBIDDEN` com mensagem "Workspace nao selecionado".

O middleware deve setar o tenant context no AsyncLocalStorage/Prisma antes de cada request do `tenantProcedure`.

```typescript
// packages/db/src/tenant-context.ts
import { AsyncLocalStorage } from 'async_hooks';

interface TenantStore {
  tenantId: string;
}

export const tenantStorage = new AsyncLocalStorage<TenantStore>();

export function getCurrentTenantId(): string | undefined {
  return tenantStorage.getStore()?.tenantId;
}

  return tenantStorage.run({ tenantId }, fn);
}
```

```typescript
// packages/business/auth/guards/permission.guard.ts
import type { Role } from '../domain/entities/tenant-member.entity';
import type { Permission } from '../domain/permissions';
import { ROLE_PERMISSIONS } from '../domain/permissions';

export function hasPermission(role: Role, permission: Permission): boolean {
  return ROLE_PERMISSIONS[role].includes(permission);
}

export function requirePermission(role: Role, permission: Permission): void {
  if (!hasPermission(role, permission)) {
    throw new Error('Permissao insuficiente');
  }
}

// Hierarquia de promocao
const ROLE_HIERARCHY: Record<Role, number> = {
  CONSULTANT: 0,
  LEADER: 1,
  DIRECTOR: 2,
  ADMIN: 3,
};

export function canPromoteTo(callerRole: Role, targetRole: Role): boolean {
  // Ninguem promove para role >= proprio
  return ROLE_HIERARCHY[targetRole] < ROLE_HIERARCHY[callerRole];
}
```

```typescript
// apps/web/src/lib/workspace-switch.ts

// Funcao chamada quando a consultora troca de workspace:
// 1. Chama auth.switchWorkspace via tRPC
// 2. Recebe novo JWT com novo tid/mid/role/plan
// 3. Limpa TODO o cache do React Query: queryClient.clear()
// 4. Limpa todas as stores Zustand: chamar reset() de cada store
// 5. Atualiza a session do Auth.js via update()
// 6. Redireciona para /dashboard

import type { AppRouter } from '@wbc/api/src/root';
import type { QueryClient } from '@tanstack/react-query';

export async function switchWorkspace(
  trpcClient: ReturnType<typeof import('@trpc/client').createTRPCClient<AppRouter>>,
  queryClient: QueryClient,
  updateSession: (data: Record<string, unknown>) => Promise<unknown>,
  tenantId: string,
  router: { push: (path: string) => void },
): Promise<void> {
  // 1. Chamar backend para obter novo JWT
  const result = await trpcClient.auth.switchWorkspace.mutate({ tenantId });

  // 2. Limpar cache do React Query
  queryClient.clear();

  // 3. Atualizar session do Auth.js com novo tenantId
  await updateSession({ tenantId: result.tenantId });

  // 4. Redirecionar para dashboard
  router.push('/dashboard');
}
```
